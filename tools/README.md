# Tools

### `data_understanding.ipynb`
A Jupyter Notebook dedicated to the initial cleaning, normalization, and exploratory data analysis of the generated forensic dataset.
- **Data Filtering:** Applies a strict Regex allowlist to remove rows containing non-Latin or non-ASCII characters, ensuring text encoding stability across all JSON list fields.
- **Taxonomy Mapping:** Automatically normalizes diverse `crime_subcategory` entries (e.g., mapping "Extortion" to "Robbery") and derives standard `crime_category` labels.
- **Visual Reporting:** Generates statistical summaries and bar charts to visualize the distribution of the normalized crime categories and the top 15 subcategories.
- **Output:** Exports the sanitized and mapped dataset to `filtered_forensic_atomic_v2.csv`.

### `post_generation_judge.py`
Runs a post-generation batch evaluation on an existing CSV dataset using the Multi-Judge Tribunal architecture.
- **Evaluation:** Queries 3 different LLMs (OpenAI, Anthropic, Google) to evaluate the logic and forensic relevance of each generated inference.
- **Consensus:** Applies a majority voting system to approve or reject the generated data.
- **Refinement:** Automatically triggers a rewrite loop via an expert model if an inference is rejected, then re-evaluates the corrected version.
- **Usage:**
    ```bash
    python tools/post_generation_judge.py --input data/forensic_atomic.csv --output data/forensic_atomic_judged.csv --workers 10
    ```

### `judgement_analysis.ipynb`
A Jupyter Notebook that aggregates and evaluates the batch logs generated by the Multi-Judge Tribunal (OpenAI, Anthropic, Gemini) to assess AI consensus and validation strictness.
- **General Overview:** Calculates global metrics such as the total number of evaluated events, overall approval rates, and rejection percentages.
- **Agreement & Performance:** Analyzes score distributions, calculates judge unanimity/split-vote rates, and tracks individual provider performance metrics.
- **Rejection Diagnostics:** Extracts and categorizes the primary rejection reasons (Derivability, Consistency, Proportionality, Integrity) for each LLM judge and investigates specific edge cases.
- **Output:** Saves a comprehensive statistical aggregation to `judgement_summary.csv`.
